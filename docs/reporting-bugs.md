# Reporting a bug

Something does not work as it should? Please tell us. Issues are how we find and fix problems.

> **Issues are public.** Never paste keys, tokens, passwords, e-mail addresses or private code in an issue. Remove them from logs and screenshots first.

## From ULU: the bug button

Newer versions of ULU have a **bug button** in the top bar, next to **Help**. It is the easiest way.

1. Press the bug button. **Report a bug** opens.
2. Tell what went wrong, in your own words: what you did, what you saw, what you expected.
3. Press **Find the cause with Claude**. Claude reads what ULU knows (versions, the runs and their cost, the team's sessions, the errors the window showed) and writes the report. This uses Claude, at most $1.50. Or press **Write it myself**.
4. Read the report. Change what is wrong in **Edit**.
5. Press **Open the issue on GitHub**. With the GitHub CLI signed in, ULU files it for you. Otherwise GitHub opens in your browser with the report filled in, and you press **Submit new issue**.

ULU leaves out your home folder, keys, tokens and e-mail addresses. Still, read the report before you send it.

## On GitHub

You can also [open an issue here](https://github.com/endorphin-ai/ulu-releases/issues/new/choose) directly. Choose **Bug report** and fill in the form.

Before you open a new one, please [search the issues](https://github.com/endorphin-ai/ulu-releases/issues). Maybe someone found it already. Then add what you know there.

## What helps us most

- **What happened**, and **what you expected**.
- **Steps**: what you did, one step at a time, so we can do it again.
- **ULU version**: at the bottom left of the ULU window, for example `v0.4.2`.
- **macOS version**: Apple menu → **About This Mac**.
- **Claude Code version**: run `claude --version` in a terminal.
- **The report ULU prepared**, if you used the bug button.
- A screenshot, if it shows the problem. Hide private things first.
